## 0. Preparación del entorno

Para el arranque (docker compose vs local), material de muestra y variables
de entorno, ver `docs/MANUAL_TEST_WEB_MVP.md` sección 0. Resumen mínimo:

```bash

# Frontend
cd web/frontend && npm run dev         # http://localhost:5173
```

**Material adicional para esta ronda**:

  `on_batch_loaded`, `on_page_changed`, `on_navigate_next`, `on_key_event`).

  ejecutar pipeline".

## 10. Workbench — atajos de teclado (16)

- [ ] **W** o **Esc** cierran el lote y navegan a `/batches`.
- [ ] **?** o **H** abre el modal de ayuda.

### 10.2 Edición
- [ ] **R** rota página 90° CW.
- [ ] **M** alterna needs_review.
- [ ] **X** alterna is_excluded.
- [ ] **P** reprocesa la página (síncrono, ver sección 14).
- [ ] **B** abre dialog "Añadir barcode".
- [ ] **Delete** elimina la página actual (con confirm).

### 10.3 Navegación
- [ ] **←** página anterior (dispara `on_navigate_prev`).
- [ ] **→** página siguiente (dispara `on_navigate_next`).
- [ ] **Shift+→** siguiente con `needs_review`.
- [ ] **Ctrl+G** dispara script de navegación custom.

### 10.4 Zoom
- [ ] **0** zoom 100%.
- [ ] **+** zoom in.
- [ ] **-** zoom out.
- [ ] **F** fit to page.

### 10.5 Filtro de foco
- [ ] Atajo dentro de un `<input>` (p. ej. metadata) **no** dispara la
      acción global (no rota la página al teclear "R" en un campo de texto).
- [ ] Atajo dentro de un `<textarea>` tampoco.
- [ ] Atajo con un modal abierto (`?` con el cheatsheet abierto) → cierra el
      modal en lugar de cerrar el lote (Esc) o reabrirlo (?).
- [ ] Pulsar **solo** Alt / Ctrl / Meta / Shift sin tecla acompañante **no**
      dispara `on_key_event` (regresión corregida en Fase 4).

### 10.6 Estado read-only
- [ ] Mientras el pipeline está corriendo, todos los atajos de edición
      (R, M, X, P, B, Delete) se ignoran o muestran mensaje.
- [ ] Mientras el transfer está corriendo, idem.
- [ ] Los atajos de navegación (←, →, Shift+→) siguen activos durante el run.

## 13. Workbench — eventos lifecycle (Fase 4)

**Preparación**: en la app de prueba, definir scripts mínimos en cada evento
(ver editor de eventos § 19). Ejemplos:

```python
# on_batch_loaded
log("BATCH LOADED")
return {"logs": ["batch ready"]}

# on_page_changed
log(f"PAGE {page.id}")
return {"logs": [f"changed to {page.page_index}"]}

# on_navigate_next
return {"target_page_id": batch.pages[-1].id}  # salta al final

# on_key_event
return {"logs": [f"got key: {key}"]}
```

### 13.1 on_batch_loaded
- [ ] Al abrir el lote, en el tab Log aparece la entrada del script.
- [ ] Cambiar el script para devolver `{cancel: true}` → al abrir, redirige
      fuera del workbench con toast informativo.
- [ ] Script con `time.sleep(10)` (forzar timeout): tras 5s aparece error
      "timeout" en log y la apertura del lote sigue (no se queda colgada).

### 13.2 on_page_changed
- [ ] Cambiar de página dispara el evento; el log refleja `page.id` correcto.
- [ ] Devolver `{fields_updated: {"foo": "bar"}}` → el campo se persiste en
      `page.fields` y se ve en el tab metadata sin refrescar.
- [ ] Script con error de sintaxis → log entry con error, no rompe la
      navegación.

### 13.3 on_navigate_prev / on_navigate_next
- [ ] ← y → disparan los eventos respectivos (verificar logs).
- [ ] `{target_page_id: N}` salta a esa página específica (no avanza ±1).
- [ ] `{target_page_id: 999999}` (no existe) → no hace nada.
- [ ] `{cancel: true}` → no navega.

### 13.4 on_key_event
- [ ] Pulsar Ctrl+Z (no mapeado) → dispara evento con `key="Ctrl+Z"`.
- [ ] Pulsar **solo** Ctrl, Alt, Shift o Meta → **no** dispara.
- [ ] Throttle: pulsar Ctrl+Z 10 veces seguidas (< 100ms) → solo dispara
      una vez por (event, page_id).

### 13.5 Persistencia y context
- [ ] En `on_page_changed`, modificar `batch.fields` desde el script
      (`return {"batch_fields_updated": {...}}`) → persiste en BD.
- [ ] `app`, `batch`, `page` están disponibles en el contexto.
- [ ] `extra` y `key` solo aparecen donde corresponde.

## 15. Workbench — pipeline run

### 15.1 Ejecución básica
- [ ] F5 (o botón Ejecutar pipeline) → barra de progreso aparece.
- [ ] WebSocket recibe `pipeline_started` → progreso 0/N.
- [ ] `page_processed` actualiza el contador página a página.
- [ ] `pipeline_completed` cierra WS, refresca lote/páginas, toast de éxito
      (o "completado con errores" si hubo fallos).
- [ ] Estado del lote pasa de `created` a `running` y luego a `read` o
      `error_read`.

### 15.2 Estado read-only durante run
- [ ] **Regresión corregida**: durante `pipeline_started` los controles de
      edición (rotate, add/delete barcode, drag-drop, context menu) deben
      quedar deshabilitados o ignorar input. Si el bug está vivo, anotar.
- [ ] Idem para `transfer_started`.
- [ ] Tras `pipeline_completed` los controles vuelven a estar activos.

### 15.3 Errores y casos límite
- [ ] Lote vacío + F5 → 409 "El lote no tiene páginas".
- [ ] Lote en `read` + F5 → comportamiento (anotar si reejecuta o bloquea).
- [ ] Cerrar pestaña a mitad: el backend sigue. Reabrir el lote → la UI
      reengancha el progreso vía WS o muestra el estado final si ya acabó.
- [ ] Imagen corrupta como input → la página se marca con error pero el
      pipeline continúa con las demás.
- [ ] Auto-transfer activado en la app + pipeline OK → transfer arranca
      automáticamente.

### 15.4 Concurrencia
- [ ] Abrir el mismo lote en dos pestañas, lanzar pipeline en una → la otra
      pestaña recibe los eventos WS y refresca igual.
