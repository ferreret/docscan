# Progreso 2026-04-22 — Configurador web cerrado y Workbench web fase 2

## Resumen

Sesión muy larga en `feature/web` que ha cerrado **cuatro sub-proyectos
completos** consecutivos: las tres pestañas restantes del configurador web
(Imagen, Campos, General), la pestaña Transferencia con sus tres eventos

## 2. Pestaña Transferencia + 3 eventos lifecycle

Sesión más sustancial del configurador. La auditoría reveló que el
`TransferService` desktop sólo soporta destinos locales (folder, PDF, PDF/A,
CSV) — no hay FTP/SFTP/SMB/S3 todavía. La pestaña web se ajustó a esos cuatro
modos y se delegó la decisión de tipos remotos a futuras fases.

Se implementó en paralelo con dos subagentes (uno frontend, otro backend) que
acordaron previamente el contrato API y los eventos WebSocket. La pestaña
añade form dinámico por modo y, en `BatchDetailView`, un botón "↗ Transferir
ahora" con listener WebSocket para progreso. El backend incorpora el endpoint
`POST /batches/{id}/transfer` con `BackgroundTasks`, runner síncrono que baja
imágenes a tempdir, y los tres firers de eventos lifecycle siguiendo el patrón
de `_fire_scan_complete` que ya teníamos.

### Endpoints nuevos
| Método | Ruta | Descripción |
|---|---|---|
| POST | `/api/batches/{batch_id}/transfer` | Dispara transferencia asíncrona (202) |

### Eventos WebSocket nuevos en `/ws/batches/{id}`
- `transfer_started`, `transfer_page`, `transfer_completed`, `transfer_error`,
  `transfer_aborted`. El WS ahora cierra también con cualquier `transfer_*` final.

### Eventos lifecycle disparados en runner
- `on_transfer_validate` (puede abortar retornando False)
- `on_transfer_advanced` (post-transferencia con resultado)
- `on_transfer_page` (callback por cada página transferida)

## 3. Sistema de tema global (Fase 1 del Workbench web)

Tras una observación del usuario ("la web no se parece nada al Workbench Qt")
se brainstormeó el sub-proyecto **Workbench web**, que se descompone en
cuatro fases. Esta sesión cerró la **Fase 1**: tema dual claro/oscuro/auto
con persistencia del usuario, aplicado a toda la web.

Se siguió el flujo `brainstorming → spec → writing-plans →
subagent-driven-development` con dispatches por task. Decisiones tomadas:

- **Paleta dual Catppuccin**: Latte (claro, ya teníamos) + Mocha (oscuro nuevo).
- **Mecanismo**: `<html data-theme="light|dark">` con CSS variables que cambian
  dinámicamente las utilities de Tailwind v4.
- **Persistencia**: `localStorage['theme']` con valores `auto|light|dark`.
- **Auto**: detecta `prefers-color-scheme` del SO en vivo (`matchMedia` listener).
- **UI del toggle**: 3 botones segmented (☀ ◐ ☾) con `role=radiogroup` +
  `aria-checked` en el card de usuario del sidebar.

La parte más laboriosa fue la **auditoría de colores hardcoded**: 22 archivos
modificados, ~100 ocurrencias (`bg-white` → `bg-base`, `text-gray-*` →
`text-text/subtext`, `bg-primary text-white` → `bg-primary text-base`, etc.).
Se documentaron 8 excepciones legítimas (badges categóricos del pipeline y
overlay de barcodes).

QA visual con Playwright en 3 vistas y 2 modos detectó un overlay claro
desentonado en miniaturas; se cambió `bg-text/80` por `bg-crust/90` para que
fuera oscuro consistentemente en ambos temas.

## Decisiones tomadas

- **Toggle de tema global y `data-theme` attribute**: la web tiene tema dual
  ahora, no sólo el Workbench. Cualquier vista respeta el modo elegido.
  Mecanismo `data-theme` (no clase `.dark`) porque permite override fácil y
  testing más directo.
- **Catppuccin Mocha como paleta oscura**: complemento natural del Latte que
  ya usábamos. Sin inventar paleta nueva.
- **vue-splitpanes para el Workbench**: librería pequeña y probada. Alternativa
  CSS Grid + ResizeObserver custom era ~150 LOC de código frágil.
- **`PipelineEvent.to_dict()` aplana payload al raíz**: documentado tras
  detectar bug. Cualquier listener WS frontend debe leer `event.X` directamente,
  no `event.payload.X`.
- **`BatchDetailView.vue` eliminado, no preservado**: el reemplazo es total.
  Se borra el fichero (560 LOC menos). Las URLs `/batches/:id` siguen iguales.
- **DocumentViewer pierde toolbar built-in**: ya no se usa fuera de
  WorkbenchView, así que se elimina la duplicación con ViewerToolbar.
- **Auditoría de colores hardcoded como parte de Fase 1**: no se posterga; sin
  ella el modo oscuro queda con cuadros blancos a media página.
