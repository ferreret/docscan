# Progreso 2026-04-10 — Storage MinIO + Frontend Vue 3 completo

## Resumen

Sesión con dos grandes bloques sobre la rama `feature/web`: primero se ha
migrado el storage de ficheros de un backend filesystem a **MinIO
(S3-compatible)** con arquitectura dual-backend configurable; después se ha
creado el **frontend Vue 3 completo** con autenticación, CRUD de aplicaciones
y lotes, upload de ficheros, ejecución de pipeline y visualización de
resultados. El frontend se ha probado de punta a punta con Playwright contra
la API real + PostgreSQL, verificando todo el flujo: registro, login, crear
app, crear lote, subir imagen, ejecutar pipeline y comprobar que el estado y
los resultados se actualizan correctamente.

## 1. Migración de storage a MinIO

El storage de ficheros de páginas (imágenes y PDFs) ha pasado de ser un
backend filesystem monolítico a una **arquitectura pluggable con dos backends**:
`FilesystemStorage` para desarrollo local y `MinIOStorage` para
producción/Docker. Ambos implementan la nueva ABC `BaseStorage` con cuatro
operaciones: `save`, `read`, `exists`, `delete`.

La selección de backend se hace vía variable de entorno
`DOCSCAN_WEB_STORAGE__BACKEND` (`"filesystem"` por defecto, `"minio"` en
Docker Compose). El factory `get_storage()` instancia el singleton adecuado.

**Cambios derivados en el resto de la API:**

- **Router de páginas**: `FileResponse` + `absolute_path()` (filesystem-only)
  reemplazado por `Response(content=storage.read(...))` con media-type correcto.
  Se ha eliminado una comprobación TOCTOU redundante (`exists()` antes de
  `read()`) que suponía un round-trip extra a MinIO.
- **Pipeline runner**: `cv2.imread(path)` reemplazado por
  `cv2.imdecode(np.frombuffer(storage.read(...)))`, compatible con ambos backends.
- **Docker Compose**: el servicio `api` ahora usa MinIO como backend por defecto,
  eliminando el volumen `api_storage` que ya no es necesario.

## Decisiones tomadas

- **Dual-backend storage**: en vez de migrar directamente a MinIO (rompiendo
  desarrollo local), se creó una ABC `BaseStorage` con factory configurable.
  Así el desarrollo local funciona sin MinIO y Docker Compose lo activa
  automáticamente.

- **Response en vez de FileResponse**: `FileResponse` requiere path en disco,
  incompatible con MinIO. `Response(content=bytes)` es agnóstico al backend.
  Para imágenes de documento (<5 MB típico) no hay problema de memoria.

- **AuthImage vía blob URL**: las alternativas (query param con token, cookie
  session) tienen implicaciones de seguridad. Fetch + blob URL es la solución
  estándar para imágenes protegidas por bearer token en SPAs.

- **Frontend MVP con Tailwind genérico**: el diseño visual no replica aún la
  estética de la app desktop. Es deliberado — priorizar fontanería (auth, CRUD,
  upload, pipeline) sobre estética. El restyling es cosmético y vendrá después.
