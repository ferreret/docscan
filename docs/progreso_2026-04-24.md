### Detalles reseñables

- **Rotación**: se verificó que los overlays rojos/azules siguen exactamente
  sobre el barcode real tras 90° CW, 180° y 270°. El campo `cliente` morado
  también se reposiciona correctamente porque el backend transforma las coords
  de *todos* los rectángulos al rotar.
- **Drag-drop**: la comprobación se hizo mirando los `src` de las miniaturas
  antes/después. Orden antes: `[7,8,12,13,14]`; después de arrastrar la 1ª
  hasta la 3ª: `[8,12,7,13,14]`. El reorder del backend es atómico como
  esperábamos.
- **Tab Log**: refleja en tiempo real cada acción del usuario (exclusión,
  revisión, borrado, reorder, add/delete barcode) con nivel + timestamp +
  source. Al recargar el lote, los errores persistidos reaparecen.
- **Bloqueo UI**: con un `time.sleep(5)` por página inyectado en el ScriptStep,
  el pipeline tarda ~25 s y deja tiempo de sobra para comprobar el estado
  `running`. Tras el fix de esta sesión, durante ese período: el badge cambia a
  "running", el botón "Rotar" queda disabled, el botón "+ Añadir" y las "×" de
  eliminar barcode desaparecen, y las miniaturas dejan de ser draggable.

## 3. Bugs encontrados y correcciones

### Bug 1 — `PageListItem` omitía `is_excluded` y `review_reason`

El endpoint `GET /api/batches/:id/pages` devolvía el resumen de página sin esos
dos campos, aunque el PATCH los persistía correctamente en BD. El template
`PageThumbnail.vue` los leía como `undefined`, con lo que los `v-if` de los
badges nunca se activaban y la UI parecía "no reaccionar" al PATCH aunque el
backend estaba perfecto.

Fix (2 líneas en `web/api/schemas/page.py`):

```python
class PageListItem(BaseModel):
    ...
    review_reason: str
    is_excluded: bool
    ...
```

Test de regresión nuevo en `TestPagesRead`:
`test_listar_paginas_incluye_flags_excluded_y_review`, que hace PATCH sobre una
página y verifica que los tres flags vienen en el listado.

### Bug 2 — UI no se bloqueaba durante `pipeline` / `transfer`

El cómputo `isReadOnly` en `WorkbenchView.vue` depende de
`store.current.state ∈ {"running", "transferring"}`. El handler de WebSocket
refrescaba ese state **solo** en `pipeline_completed` y `transfer_completed`,
por lo que durante la ejecución el badge seguía diciendo "read" y todos los
controles de edición seguían habilitados. Era fácilmente reproducible porque el
pipeline normal tarda décimas de segundo; solo con el `time.sleep(5)` inyectado
se manifestaba el problema.

Fix (2 líneas en `web/frontend/src/views/batches/WorkbenchView.vue`): añadir
`await store.fetchOne(batchId.value)` al procesar los eventos
`pipeline_started` y `transfer_started`.

Tras el fix, el flujo completo funciona:
`pipeline_started` → fetchOne → `state='running'` → `isReadOnly=true` →
todos los controles en cascada (ViewerToolbar.canRotate, BarcodePanel.readOnly,
ThumbnailPanel.readOnly, ThumbnailContextMenu.readOnly) se bloquean.

Commit único: **`aa87748 fix(web): exponer flags de exclusión/revisión y
refrescar estado durante run`**.

## Decisiones tomadas

- **Arreglar en el día los 2 bugs encontrados**: son ambos de 1-2 líneas,
  están cubiertos por observación directa en el navegador, y dejar la Fase 3
  "QA OK con 2 bugs abiertos" sería peor que retrasar media hora el informe.
- **Añadir solo test backend**, no frontend: el test backend del schema es
  trivial y garantiza regresión. Un test frontend que cubra el refetch en
  `pipeline_started` requiere mockear WebSocket + store y se pospone al
  seguimiento de Fase 4.
- **Diálogo de "eliminar desde aquí" queda sin contador**: el plan pedía "Se
  eliminarán N páginas", pero el diálogo actual solo pregunta "¿Eliminar desde
  esta página hasta el final?". Es una mejora de UX menor, no bloqueante, se
  apunta para Fase 4.
- **Contadores "Con barcode" y "Separadores" siguen en 0**: ya era follow-up
  conocido que requiere agregación backend (documentado en MEMORY). No se
  aborda en esta sesión.
