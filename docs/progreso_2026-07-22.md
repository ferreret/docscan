# Progreso 2026-07-22 — Suite no interactiva, Python 3.14, webhook y upgrades de dependencias

## Resumen

Sesión de trabajo sobre `main`, continuación del saneamiento del desktop cerrado
ayer (release v0.1.3). Se atacaron los follow-ups pendientes de la auditoría: se
hizo la batería de tests totalmente automática (sin clics ni contraseñas de
administrador), se eliminó de raíz la divergencia de versiones de Python que
había causado un bug de portabilidad, se puso al día el informe de proyecto, se
limpió el repositorio y se implementó una funcionalidad nueva de extremo a
extremo: **notificaciones webhook configurables por aplicación**.

En una segunda tanda del mismo día se acometió, además, el último follow-up de
mayor riesgo de la auditoría: la **actualización de las dependencias mayores**
(visión por computador, SDK de IA e interfaz gráfica), pendiente de una sesión
dedicada por su potencial de incompatibilidades.

## 1. Batería de tests no interactiva y sin hardware

La suite podía quedarse bloqueada esperando que alguien pulsara «Aceptar» en un
diálogo, y algún test intentaba abrir el escáner físico por USB, lo que hacía
que el sistema pidiera **contraseña de administrador** y tardaba más de 30
segundos. Ambos problemas se han cerrado con una configuración global de tests
(`tests/conftest.py`) que: simula todos los diálogos de la interfaz para que
nunca esperen una respuesta manual; sustituye la capa del escáner por un doble
inofensivo para que ningún test toque hardware real; y descarta automáticamente
los tests de la parte web archivada cuando no están sus dependencias.

Como consecuencia, la batería de integración continua se simplificó: ya no hace
falta enumerar a mano los tests a excluir, porque la nueva configuración lo
resuelve sola.

### Tests

`pytest` ahora se ejecuta sin ninguna intervención: **861 tests en ~24 segundos**,
cero interacción, cero acceso a hardware.

Commits: **`41dcc6d test: conftest global que hermetiza la suite`**,
**`e4f84ef ci: delega el descarte de tests web al conftest`**

## 2. Unificación del proyecto en Python 3.14

El proyecto se desarrollaba en Python 3.14 pero la integración continua y los
instaladores se construían con Python 3.13. Esa divergencia fue la que provocó,
en la sesión anterior, un bug de portabilidad que impedía importar el código en
3.13. Mantener dos versiones era una fuente de errores latentes, y —al tratarse
de una aplicación empaquetada que lleva su propio intérprete— la compatibilidad
con 3.13 no aportaba nada al usuario final.

Se decidió **unificar toda la cadena en Python 3.14**: desarrollo, integración
continua, documentación e instaladores usan ahora la misma versión. Se verificó
previamente que todas las librerías críticas (interfaz gráfica, visión por
computador, imágenes, PDF y el empaquetador) funcionan en 3.14. La integración
continua se ejecutó tras el cambio y quedó **en verde**, confirmando que la
divergencia está cerrada de raíz.

Commits: **`4e6f5d9 build: unifica el toolchain en Python 3.14`**,
**`b58feab style: ruff format bajo py314`**

## 4. Notificaciones webhook configurables por aplicación

Hasta hoy, el sistema tenía el motor de notificaciones implementado pero **sin
forma de configurarlo**: al terminar la transferencia de un lote, el aviso HTTP
(webhook) nunca se enviaba porque no había dónde guardar su dirección. Se ha
cerrado ese hueco de principio a fin.

Ahora cada aplicación tiene una pestaña nueva, **«Notificaciones»**, en su
configurador, donde se define la dirección del webhook, el método, las cabeceras
HTTP y el tiempo de espera, con un interruptor para activarlo o desactivarlo. Al
completar (o fallar) la transferencia de un lote, el proceso desatendido envía
automáticamente el aviso a esa dirección con los datos del lote. La configuración
se guarda por aplicación y viaja al exportar o importar aplicaciones.

La estructura de datos se diseñó dejando sitio para el envío por email (SMTP) en
el futuro sin necesidad de una nueva migración de base de datos.

## 5. Actualización de dependencias mayores

El proyecto arrastraba varias librerías clave rezagadas respecto a sus versiones
actuales, y tres de ellas implicaban saltos de riesgo: la librería de **visión
por computador** (OpenCV), que estrenaba versión mayor 5.0 con cambios de fondo;
el **SDK de inteligencia artificial** de Anthropic, con más de treinta versiones
de diferencia; y el **framework de interfaz gráfica** (PySide6). Actualizarlas se
había reservado para una sesión propia por el riesgo de romper la aplicación.

El trabajo se hizo por fases y con red de seguridad: se partió de una rama
dedicada y de una copia de respaldo del entorno para poder revertir, y **tras
actualizar cada grupo de librerías se ejecutó la batería completa de tests**
(879 en cada pasada), agrupando cada grupo en su propio commit para poder aislar
cualquier problema. Antes de tocar nada se comprobó, con la documentación oficial
de cada librería, que los cambios de fondo no afectaban a cómo el proyecto las
usa —en el caso de OpenCV, la aplicación solo emplea funciones básicas de
tratamiento de imagen, ajenas a las partes que la versión 5 reorganiza— y que
existían paquetes compatibles con Python 3.14 para todas.

El resultado es que las siete librerías quedaron al día **sin necesidad de
cambiar una sola línea de código**: ninguna de las funciones que el proyecto
utiliza cambió de forma. Además de los tests, se ejecutó una comprobación de
arranque que carga los servicios de imagen, código de barras e IA y construye los
clientes de IA reales, todo correcto.

## Decisiones tomadas

- **Unificar en Python 3.14 en vez de mantener 3.13**: al ser una aplicación
  empaquetada con su propio intérprete, la compatibilidad con 3.13 no beneficia
  al usuario final; unificar elimina la divergencia que causaba bugs.
- **Solo webhook ahora, email SMTP después**: el email introduce el manejo de
  credenciales SMTP, que exigen cifrado; se acota el alcance para entregar valor
  antes. La estructura de datos ya contempla el email.
- **Columna y pestaña dedicadas para notificaciones**: separación limpia frente a
  mezclar la configuración con la de transferencia o la de IA.
- **Borrar la rama `production`**: no tenía ningún cambio propio, todo estaba ya
  en `main`.
