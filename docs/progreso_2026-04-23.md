# Progreso 2026-04-23 — Workbench web Fase 3 completa

## Resumen

Sesión intensiva en `feature/web` que ha cerrado la **Fase 3 del sub-proyecto
Workbench web** (edición, log y read-only) de forma íntegra. Tras el
brainstorming inicial, spec, plan detallado de 24 tasks TDD y ejecución
subagent-driven con doble revisión (spec + code quality) en cada task, el
Workbench web alcanza paridad funcional con el Workbench desktop para la
operativa diaria: rotación de páginas, overlays de campos con toggles,
edición manual de barcodes, menú contextual con 4 acciones por página,
reordenado drag-drop y tab Log funcional, todo bloqueado correctamente
mientras el lote se está procesando.

**33 commits** en total, **495 tests passing** (171 backend + 324 frontend),
0 fallos. La rama está pendiente de push.

## 2. Backend — Tasks 1 a 9 (9 commits principales + 4 follow-ups de review)

Todas las mutaciones de página se exponen vía API con guards de tenant,
estado del lote y validación de payload.

### Endpoints nuevos

| Método | Ruta | Descripción |
|---|---|---|
| PATCH | `/api/pages/:id` | Toggle `is_excluded`, `needs_review`, `review_reason` |
| POST | `/api/pages/:id/rotate` | Rotación destructiva N×90° CW con ajuste coords barcodes |
| POST | `/api/pages/:id/barcodes` | Añadir barcode manual |
| DELETE | `/api/pages/:id/barcodes/:bid` | Eliminar barcode de una página |
| POST | `/api/batches/:id/reorder` | Reordenar páginas del lote (`page_index` atómico) |
| DELETE | `/api/batches/:id/pages/after/:pid` | Eliminar página y todas las siguientes |

Además se añadieron guards 409 a los endpoints existentes `POST /run` y
`POST /transfer` cuando el lote ya está en ejecución.

### Infraestructura común

- **`Batch.state`** extendido con los valores transitorios `"running"` y
  `"transferring"`. Sin migración (la columna es `String(20)`).
- **Ambos runners** (pipeline y transfer) refactorizados con `try/finally`
  que garantiza siempre un estado terminal (`read` / `error_read`) al salir,
  incluso si la ejecución crashea. La función interna se extrae como
  `_execute_pipeline` / `_execute_transfer` para poder parchearla en tests.
- **Helper `ensure_batch_mutable(batch, action)`** en `_helpers.py` después
  de detectar la duplicación del guard 409 en los 4 primeros endpoints.
  Unifica el mensaje y permite personalizar el verbo por acción.
- **Helper `_get_page_for_user(page_id, tenant_id, db)`** para carga de
  página con JOIN + filtrado por tenant en una consulta. 404 en mismatch.
- **Evento WebSocket `page_updated`**: nuevo helper `broadcast_page_updated`
  en `ws.py` reutiliza el `PipelineEventBus` existente (thread-safe via
  `call_soon_threadsafe`). Emitido tras el `db.commit()` de los 7 endpoints
  de mutación de página. Payload: `{type, page_id, action, extra…}` con
  `action ∈ {flags, rotated, barcode_added, barcode_deleted, deleted,
  reordered}`. `delete-after` emite un evento agregado con `deleted_ids` y
  `batch_page_count`.
- **Schema `DeletePagesResult`** para el response tipado de `delete-after`.

### Detalles reseñables

- **Rotación destructiva**: `POST /rotate` lee la imagen, la rota N veces
  90° CW con `cv2.rotate`, actualiza las coords `pos_x/y/w/h` de cada
  barcode con la fórmula per-turn `new_x = h - old_y - old_h; new_y = old_x;
  new_w = old_h; new_h = old_w` intercambiando `h/w` entre iteraciones, y
  escribe con `ImageLib.save` (preserva DPI, calidad JPEG, compresión TIFF).
  Orden crítico para atomicidad: coords actualizadas en sesión → `db.flush`
  → escritura de imagen → `db.commit`. Si el flush falla, la imagen no se
  modifica.
- **Reorder**: verifica que el set de `page_ids` del payload coincide
  exactamente con las páginas del lote (detecta ids ajenos, faltantes,
  sobrantes y duplicados) antes de actualizar `page_index`. 422 si no
  coincide.
- **Delete-after**: elimina la página anchor + todas las con `page_index >=
  anchor.page_index`, best-effort sobre el fichero en storage, recálculo
  exacto de `batch.page_count` con un `COUNT(*)` tras el flush.
- **Review de code-reviewer corrigió** varios puntos tras la primera
  implementación: `review_reason` ahora se auto-borra al hacer
  `needs_review=false`, rotate usa `ImageLib.save` en vez de `cv2.imwrite`
  (preserva calidad JPEG), validación de `turns` movida a Pydantic `Field`,
  whitespace-only rechazado al añadir barcode, tests extendidos para
  cubrir cross-page 404, tenant 404 y casos edge.

### Tests

- **Backend**: +11 clases de test en `tests/test_web_api.py`:
  `TestRunnersState` (3), `TestPagesPatch` (7), `TestPagesRotate` (7),
  `TestPagesBarcodes` (12), `TestBatchesReorder` (5),
  `TestBatchesDeleteAfter` (6), nuevos casos 409 en `TestPipelineRun`/
  `TestTransferEndpoint` (4), `TestWsPageUpdated` (7). Total: **+51 tests
  backend**, de 120 anteriores a **171 actuales**.

## 3. Frontend — Tasks 10 a 22 (13 commits + 5 follow-ups)

### Composables nuevos

- **`useOverlayToggles`** — estado `{showBarcodes, showFields}` con
  persistencia localStorage (clave `workbench.overlays`, defaults `true/true`),
  robusto frente a JSON corrupto, try/catch en setItem (Safari private mode).
- **`usePageActions`** — wrapper fino sobre 8 llamadas HTTP a los endpoints
  backend. Cada método es un alias directo sobre `api.patch/post/delete` sin
  lógica adicional; rollback y error handling son responsabilidad del
  consumidor. Detectamos en code review que `deletePage` apuntaba a URL
  incorrecta (`/pages/:id` en vez de `/batches/:bid/pages/:pid`); corregido.
- **`useWorkbenchLog`** — singleton module-level con `entries`,
  `filteredEntries`, `filterLevel`, `append`, `appendFromEvent`,
  `loadPersistedErrors`, `clear`. Mapea los 10 tipos de eventos WS
  (`pipeline_*`, `transfer_*`, `page_updated`) a `LogEntry`s con nivel y
  source. Carga errores de `processing_errors_json` y `script_errors_json`
  de las páginas al abrir el lote. Cap de 5000 entries.

### Componentes nuevos

- **`ThumbnailContextMenu`** — menú flotante right-click con 4 acciones
  (toggle excluida, toggle revisión, eliminar, eliminar desde aquí). Labels
  dinámicos según estado, cierre con ESC o click fuera, `role=menu` /
  `role=menuitem` para accesibilidad, `readOnly` deshabilita todo. 13 tests.
- **`AddBarcodeDialog`** — modal con input `value` (trim + no-blank) y
  select `symbology` (8 opciones, MANUAL default). Reset al abrir.
- **`DeleteBarcodeDialog`** — modal de confirmación con valor mostrado.
- **`LogPanel`** — consume `useWorkbenchLog`, filtro por nivel, botón
  Limpiar, color por nivel (Catppuccin), contador de entries visibles,
  empty state en español.

### Componentes extendidos

- **`DocumentViewer`** — nuevas props `fields`, `showBarcodes`, `showFields`.
  Pinta overlays de fields con `{x,y,w,h,value}` usando una paleta distinta
  a la de barcodes. Etiqueta "nombre: valor" o solo nombre si value vacío.
  Validación robusta (descarta no-dicts, coords 0, w/h negativos).
- **`ViewerToolbar`** — dropdown rotar con 3 opciones (90°/180°/270°) que
  emite `rotate(turns)`. Dos toggles independientes para overlay barcodes y
  fields con `aria-pressed`. `canRotate=false` deshabilita con tooltip.
  Click fuera cierra el dropdown.
- **`ThumbnailPanel`** — integrado con `vue-draggable-plus` (nueva dep) para
  reorder. Emite `reorder(newOrder: number[])` y `contextmenu(pageId, x, y)`.
  `readOnly` deshabilita el drag y el emit. Empty state preservado.
- **`PageThumbnail`** — badges `⊘` (excluida) y `⚐` (revisión) superpuestos
  sobre la miniatura, coloreados con `bg-danger`/`bg-warning` Catppuccin.
- **`BarcodePanel`** — de view-only a editable: botón "+ Añadir" en el
  header, botón `×` por fila, nueva prop `readOnly` oculta ambos.
- **`MetadataPanel`** — activado el tab "Log" (antes deshabilitado). Label
  muestra contador de warnings+errors entre paréntesis en color warning
  cuando > 0.

## 4. Task 23 — Integración final en `WorkbenchView.vue`

La orquestación completa: `+566 / -8` líneas en una sola task. El componente
pasa de 339 a 629 LOC, dentro de tolerancia.

### Wiring realizado

- `isReadOnly` computed propagado a `ThumbnailPanel`, `BarcodePanel`,
  `ViewerToolbar` (como `canRotate: !isReadOnly`) y `ThumbnailContextMenu`.
- `useOverlayToggles` alimenta `DocumentViewer` y `ViewerToolbar`; handlers
  `onToggleBarcodes/Fields` mutan los refs del composable.
- Listener WS extendido: cada evento pasa primero por
  `log.appendFromEvent(event)` para alimentar el log; en `page_updated`
  refresca `batch`, `pages` y la página actual si coincide.
- `loadPersistedErrors` ejecutado con `watch` sobre `store.pages`.
- Right-click sobre ThumbnailPanel abre `ThumbnailContextMenu` con coords
  correctas; cada acción llama a `pageActions.*` y refresca tras éxito.
- Reorder con refetch del backend en caso de error (rollback).
- Rotate fuerza cache-bust de imagen mediante `imageCacheTick = Date.now()`
  y `?v=${tick}` en la URL.
- `AddBarcodeDialog` y `DeleteBarcodeDialog` controlados por refs de estado,
  abiertos desde los emits de `BarcodePanel`.
- `handleApiError` centralizado con toasts diferenciados para 409 / 404 /
  otros.
- Overlay de fields: parseo de `currentPage.index_fields_json` pasado a
  `DocumentViewer`.

### Review loop

El code reviewer encontró 4 issues Important:
- WebSocket leak en unmount (si el usuario navega mientras corre un
  pipeline o transfer, el socket se queda abierto y el handler sigue
  ejecutándose sobre un componente desmontado).
- Dead code en rollback de reorder (`originalOrder` capturado y desechado).
- `counters` computado mal — reportaba valores erróneos para `withBarcode`
  y `separators` porque solo tenemos los barcodes de la página actual.
- Test isolation: `log.clear()` solo inline, sin `beforeEach` compartido.

Todos los 4 corregidos: `activeWs` ref + `onUnmounted` cleanup + guardia
`activeWs.value !== ws` en cada `onmessage` para ignorar mensajes tardíos;
`originalOrder` eliminado; `counters` simplificado a lo que podemos saber
(total y needsReview); `log.clear` movido a `beforeEach`.

## Decisiones tomadas

- **Alcance Fase 3**: las 6 features en una única fase, como estaba
  originalmente planeado en la Fase 2. No se dividió porque las features
  comparten infra (read-only cascade, evento WS).
- **Rotación destructiva**: imita desktop (`workbench_window.py:_on_rotate_90`).
  Sin campo `rotation` en el modelo. Imagen en disco sobrescrita,
  coords de barcodes actualizadas.
- **Log sin persistencia dedicada**: se alimenta de WS en vivo + errores
  persistidos en `processing_errors_json`/`script_errors_json` de las
  páginas. Sin tabla nueva.
- **Menú contextual para acciones de página**: thumbnail queda limpio, las
  4 acciones caben sin problema, atajos de teclado siguen disponibles para
  Fase 4. Descartado el modo "iconos al hover" por falta de espacio en
  thumbnails de 96px.
- **Dos toggles independientes** para barcodes y fields, persistidos en
  localStorage. Descartado el toggle único unificado.
- **`ensure_batch_mutable` helper**: detectado el patrón duplicado en los
  primeros 4 endpoints backend; extraído a `_helpers.py` en la Task 4
  review. El 5º, 6º y 7º endpoints ya lo reutilizan limpiamente.
- **`batch.state` extendido en lugar de nueva columna**: sin migración, los
  runners gestionan la transición con `try/finally`.
- **Rollback de reorder vía refetch**: en error, recargamos las páginas del
  backend. El orden auténtico está en el servidor.
