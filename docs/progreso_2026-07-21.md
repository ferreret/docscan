# Progreso 2026-07-21 — Auditoría del desktop y saneamiento P0/P1

## Resumen

Sesión de retoma tras un parón largo. Se tomó la decisión estratégica de
**archivar la versión web SaaS** y centrar el proyecto exclusivamente en
DocScan Desktop. Sobre esa base se hizo una **auditoría completa** del código
desktop y se ejecutaron las correcciones prioritarias (P0 y P1). Todo el
trabajo está en la rama `fix/auditoria-desktop-p0-p1` (9 commits sobre `main`),
con la suite de tests en verde.

## 1. Auditoría de estado

Se revisó el proyecto en cuatro frentes: calidad de código contra las reglas
del proyecto, inventario de deuda técnica y documentación, cobertura de tests
y seguridad de dependencias. Conclusión general: **el núcleo está sano** —
pipeline, motor de scripts, gestión de base de datos y capa de hilos Qt cumplen
las reglas críticas sin excepciones. La cobertura global es del 65%.

El informe completo quedó en `docs/auditoria_desktop_2026-07-21.md`, con un plan
de acción priorizado en tres niveles.

## 2. Corrección de errores y seguridad (P0)

- **Bug del modo directo**: `main.py` importaba una función inexistente
  (`get_scanner`) en vez de `create_scanner`, lo que rompía por completo el modo
  `--direct-mode` (headless). El error quedaba silenciado por un `try/except`,
  así que llevaba tiempo roto sin que nadie lo detectara. Se corrigió y se
  añadieron 3 tests de regresión del flujo completo.
- **Dependencias con vulnerabilidades**: `pip-audit` reportaba CVEs conocidos.
  Se actualizaron Pillow (12.1.1 → 12.3.0; superficie directa, la app procesa
  imágenes externas), cryptography (46 → 48.0.1; usada para cifrar las API keys),
  pydantic-settings y pytest. Tras la actualización, `pip-audit` queda limpio.

Commits: **`bb5db7a fix(main): repara --direct-mode`**,
**`0e22220 deps: actualiza pillow, cryptography, ...`**

## 4. Robustez de la suite de tests

Durante el barrido afloraron dos tests frágiles (pre-existentes, no
introducidos en esta sesión) que podían **colgar la suite entera**:

1. Un test del launcher invocaba un diálogo modal (`QMessageBox.warning`) sin
   mockear, que bloqueaba el hilo esperando un clic que nunca llegaba. **Corregido**.
2. `test_scanner_service.py` hace enumeración **real** de escáneres SANE (lento,
   ~33 s, y capaz de colgarse según el estado del hardware). Se documentó como
   follow-up (mockear la capa SANE) y se aísla en CI.

Para blindar la suite se añadió `pytest.ini` con un **timeout por defecto**: un
cuelgue ahora se convierte en un fallo con nombre en vez de bloquear todo.

Commit: **`63706f9 test(launcher): mockea QMessageBox.warning`**

## 6. Portabilidad Python 3.13 (destapado por el CI)

Al activar el CI, este falló en el paso de tests. Investigando con los logs
(vía `gh`), afloró un bug latente: **20 bloques** usaban `except A, B:` sin
paréntesis, una sintaxis que **solo acepta Python 3.14** (PEP 758). El proyecto
se desarrolla en 3.14, pero el CI y los instaladores se construyen en **Python
3.13**, donde eso es un error de sintaxis y el código no llegaba ni a importarse.

Se corrigió a `except (A, B):` (válido en todas las versiones). Un detalle sutil:
`ruff format` con `target-version = py314` **eliminaba** de nuevo los paréntesis;
hubo que fijar `ruff.toml` a `py313` para estabilizar el arreglo. El entorno de
desarrollo (3.14) y el de build (3.13) llevaban divergiendo en silencio; el
nuevo CI cierra ese hueco.

## Decisiones tomadas

- **Archivar la web SaaS, no borrarla**: todo el trabajo web queda en `main` y
  ramas pusheadas; solo se reorienta el foco. Reversible si algún día se retoma.
- **Ignorar E731 en ruff en vez de reescribir 11 lambdas**: el patrón
  `_tr = lambda s: translate(...)` de i18n perezoso es intencional y consistente;
  documentado en `ruff.toml`.
- **No mockear SANE ahora**: es un follow-up más grande; de momento se aísla el
  test de hardware con `--ignore` para no bloquear la iteración.
