Al presentar un diseño por secciones durante el brainstorming de Superpowers,
NO pausar después de cada sección preguntando "¿ok seguir?". Presentar todas
las secciones de un tirón y pedir feedback solo al final.

**Why:** El usuario dijo explícitamente "Al final sabré si me interesa o no
cuando lo pruebe, mientras tanto, tira hacia adelante". La validación
sección-a-sección le resulta pesada cuando ya se han tomado las decisiones
clave en las clarifying questions previas.

**How to apply:** Solo para DocScan Studio. Después de las clarifying
questions (que sí se responden una a una), presentar el diseño completo en
un único mensaje. El spec file se escribe después, y la revisión del
usuario ocurre contra el spec escrito, no contra el diseño dibujado en
chat.
